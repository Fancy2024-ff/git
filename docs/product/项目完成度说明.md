# 项目完成度说明（汇报版）

> 截至最近一次提交（`ea91a80`）。本文如实说明：**做得最好的部分、还没完善的部分、当前处于什么阶段**。
> 原则：不夸大、不把"框架就位"说成"功能完成"、不把"mock 验证"说成"真实跑通"。

---

## 一、一句话定位

**Mini App Factory 当前处于「能力工厂骨架成型、单条复杂能力线打样跑通」阶段。**
从市场数据 → 需求决策 → 分类 → 代码生成 → 构建 QA → 上架链路已端到端贯通；
但多数"真实运行能力"（图像/OCR/语音/视频）和"真实上架"仍待接入外部 provider 与凭据。

可类比为：**生产线和质检台已建好、跑通了一条样板产品；但大部分原料供应商（provider）还没签约。**

---

## 二、做得最好的部分（可对外展示、有测试有证据）

### 1. 端到端流水线闭环（最成熟）
从 `python core/pipeline/runner.py --mode demo` 一条命令跑完 11+ 步：
市场输入 → 需求分析 → 缺口检查 → 机会评分 → **产品决策** → PRD → 代码生成 → 上架材料 → 提交包 → **构建+QA** → 就绪评估。
- QACheckAgent 是**真实执行**：真跑 `npm install` + `npm run build:mp-weixin`，产出可导入微信开发者工具的 `dist/build/mp-weixin`。
- 全程产出结构化 artifact，状态可追踪。

### 2. 需求分析决策框架（本阶段重点升级）
不再只给一个需求分，升级为**双总分 + 8 维度 + 执行建议**：
- market_opportunity_score（市场机会）vs miniapp_feasibility_score（小程序落地性）分离
- 能正确判断「热门≠适合直接做」：Canva 类 → split_then_execute（拆分），不会误判立即执行
- 详见 `需求分析与机会判断说明.md` / `DEMAND_ANALYSIS_FRAMEWORK.md`

### 3. 能力工厂分层架构（设计扎实）
capabilities（6 类能力统一适配）/ runtime（统一任务模型）/ platforms（平台层公共骨架）/
integrations（外部 provider 唯一落点）/ generator（6 类模板矩阵）—— 分层清晰，单一事实源，
换 provider / 加平台不改业务层。

### 4. 诚实的状态表达（区别于"假完成"）
系统能如实区分：可构建 / 能力可执行 / 小程序自身可运行；可上传 / 已上传 / 可提审。
未接入的能力一律 `provider_missing`，绝不假成功。这是工程成熟度的体现。

### 5. 测试覆盖（有据可查）
- 后端 **146** + 前端 **65** + 生成器 **9** = **220 项自动化测试全过**
- 覆盖：分类、能力注册、runtime 任务模型、image 链路、微信上传、就绪度契约、决策框架、模板归一化等

### 6. 微信上传链路（第一条真实平台出口）
miniprogram-ci 开发版上传已接通，dist→上传→submit-status/readiness 联动。
（真实上传需配 AppID+密钥；当前用 mock subprocess 验证代码路径一致。）

## 三、还没完善的部分（诚实清单）

### 1. 真实外部能力 provider 大多未接（最关键缺口）
能力层真实状态（`registry.build_capability_snapshot`）：

| 能力 | 状态 | 说明 |
|---|---|---|
| text.generate | ✅ configured | 真实可用（中转站 LLM） |
| utility.execute | ✅ runtime_ready | 本地能力，无需 provider |
| image.process | ❌ provider_missing | 接口/任务模型就位，**缺真实图像 provider key**（目前 mock 验证链路） |
| vision.ocr | ❌ provider_missing | 仅 stub |
| speech.tts/asr | ❌ provider_missing | 仅 stub |
| video.process | ❌ provider_missing | 仅 stub |

→ 即：**生成的小程序大多是"可上架空壳"**，要真能用还需接对应 provider。

### 2. 真实上架未完成
- 微信：仅"开发版上传"代码就位，**自动提交审核未做**（仍需人工去后台提审）；且未用真实凭据实跑。
- 其它平台（支付宝/抖音/Telegram/Reddit…）：平台注册表已登记，但 **upload 全部 not_implemented**，仅微信 implemented。

### 3. 主链路是规则驱动，非 LLM
需求分析/机会判断/决策主链路是**写死的可解释规则**，`USE_LLM=true` 才走 LLM 且默认未启用；
平台缺口判断是本地启发式（未真去各平台搜索）；需求分析"更新频率"维度是占位默认值。

### 4. 目标架构尚未完全落位
对照最终目标架构，以下目录**还没建/未到位**：
- `apps/worker` ❌（7×24 调度、自动扫描、复盘 —— 未建）
- `core/domain` ❌（领域模型/枚举单一事实源 —— 未建，现散在各处）
- `core/persistence` ❌（repository/DB —— 未建，现为 JSON 文件 + 雏形）
- `core/classification` 位置偏差：实际在 `core/agents/classification/`，未迁到 `core/classification/`

### 5. 其它已知简化
- 数据库为 JSON 文件（非 SQLite/PG），单 worker + 全局状态，不支持并发流水线
- App 搜集层（七麦/SensorTower 真实榜单）未接，demo 用样例数据
- LLM 增强目前只补文字解释，未让 LLM 重算评分维度
